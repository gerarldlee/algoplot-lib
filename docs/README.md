# algoplot documentation

Guides (this site) + API reference (TypeDoc), built statically and published to
GitHub Pages by CI.

```bash
npm install
npm run docs          # dev server at localhost:4321
npm run docs:build    # TypeDoc → docs/public/api, then astro build → docs/dist
```

Both halves land in one site: the Astro output is `docs/dist`, and TypeDoc writes
`docs/public/api`, which Astro copies verbatim — so the deployed site serves the
guides at `/` and the API at `/api/`.

## Layout

```
docs/
  astro.config.mjs       remarkPlugins: [[remarkAlgoplot, { mode: 'html' }]]
  src/layouts/Base.astro nav, palette, registers <algoplot-player> (script import)
  src/styles/global.css  theme — same custom-property names as the player's sheet
  src/pages/index.astro  landing
  src/pages/guides/*.md  one file per guide, `layout` frontmatter
  public/api/**          generated by `npm run api` — never edit
```

## How the fences run

`astro.config.mjs` loads `@algoplot/remark` with `mode: 'html'`, so every
`​```algoplot` fence in `src/pages/**` executes at build time and is replaced by an
`<algoplot-player data-payload="…">` node. `Base.astro` imports
`@algoplot/element`, which registers the component on page load. A fence that throws
or exceeds its budget **fails `npm run docs:build`** with the file, fence position and
error line — the same contract any consumer gets.

Python fences work because `@algoplot/python` and `pyodide` are dev dependencies of
this workspace (loaded from the npm package, not a CDN, during the build).

## Adding a guide

1. Create `src/pages/guides/<slug>.md` with frontmatter
   `title`, `description`, `layout: ../layouts/Base.astro`.
2. Link it from `Base.astro`'s `guides` array (nav) — the array is the only list.
3. Use *relative* links between pages (`fences/`, `../api/`), so the site works
   behind a project-page base path.

## Base path

CI sets `DOCS_BASE=/<repo>` when the site is served from a GitHub project page
(`https://<owner>.github.io/<repo>/`); locally it is empty (root). `Base.astro` builds
navigation through `import.meta.env.BASE_URL`, and guide links stay relative — that is
the whole portability story.

## TypeDoc

`typedoc.json` at the repo root points at the five package entry points and excludes
tests. It type-checks the sources with the root `tsconfig.json` (including
`vite/client` types for `?raw`/`?inline` imports), so a docs build is also a second
typecheck of the public surface.
